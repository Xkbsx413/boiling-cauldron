## P1：补生存模式获取入口（已完成并测试通过）

### 问题

生姜、大蒜、贡菜、花椒目前存在生存模式获取死循环：

- 种子只能由对应作物合成（`ModRecipeProvider.java:49-67`）。
- 作物又必须用对应种子种植。
- 没有野生作物、草方块掉落、村庄箱子、流浪商人交易或其他初始来源。
- 因此新世界生存模式无法获得第一批种子，只能在创造模式或使用指令后开始种植。

其他材料已经有入口，不受此问题影响：

- 冬笋、竹荪可以通过竹根殖块繁殖获得。
- 盛花荷叶可以通过原版荷叶 + 花朵合成，再转化为藏藕泥块并获取莲藕。

### 目标

- 新世界生存模式不依赖创造模式、指令或其他模组，能够获得第一批生姜、大蒜、贡菜、花椒种子。
- 保留现有“作物 → 种子 → 扩大种植”的循环。
- 不破坏现有掉落表和合成配方。
- 获取方式应有明确提示，玩家不需要查源码猜测。

### 可选方案

1. **野外地物**
   - 在特定生物群系生成少量野生作物或种子。
   - 优点：沉浸感最好，探索有回报。
   - 缺点：需要 worldgen、生物群系标签和生成密度调优，工作量最大。

2. **草方块/蕨类掉落**
   - 破坏草或蕨时低概率掉落种子。
   - 优点：实现简单，玩家容易发现。
   - 缺点：四种作物都用同一种来源会缺乏区分度，且可能影响平衡。

3. **村庄箱子战利品**
   - 向不同村庄类型的箱子注入对应种子。
   - 优点：自然、低风险，容易通过数据包实现。
   - 缺点：依赖玩家找到村庄，且需要避免与其他模组的战利品表冲突。

4. **流浪商人交易**
   - 增加用绿宝石换种子的交易项。
   - 优点：稳定、可重复获取，适合作为保底来源。
   - 缺点：需要等待商人出现，前期节奏不可控。

5. **替代合成配方**
   - 用其他容易获得的材料合成首批种子。
   - 优点：实现最简单。
   - 缺点：容易显得突兀，需要合理设计材料。

6. **森罗厨房市场/交易整合**
   - 如果森罗厨房已有市场或交易系统，可以把种子接入其商品列表。
   - 优点：与前置模组联动自然。
   - 缺点：需要确认森罗厨房对应 API 和版本兼容性。

## P2：实现钵钵鸡（代码已实现，待重新构建和游戏测试）

### 目标

实现第一条完整的成品玩法链：

1. 放置 `bobo_chicken_pot`。
2. 水桶加水。
3. 放入一种底料，获得 64 次浸泡额度。
4. 在 4×4 共 16 格中放入食物，每格独立浸泡 60 秒。
5. 完成后右键取得 `bobo_chicken`。
6. 食用后获得对应底料效果。

- 详细规则见 `docs/design.md` 第 2 节。

### 最终设计（2026-10-31）

#### 容器与容量

- 方块 `bobo_chicken_pot` + BlockEntity。
- 4×4 共 16 格，每格最多 1 个食物，不可堆叠。
- 每格独立 60 秒计时；移动或取出食物会清零该格进度，底料次数不返还。
- 绿色进度条，完成时满条；GUI 每 10 tick 同步一次；区块卸载时暂停。
- GUI 采用原版槽位交互；不设碗，右键成品直接拿到光标。
- 第一版建议不接入漏斗等自动化，避免状态同步和复制问题。

#### 水、底料与冲洗

- 初始状态为“空”。
- 水桶右键加水，消耗水桶并返还空桶，状态变为“水”。
- 只有“水”状态、16 格全空、底料计数为 0 时，才能放入 1 个底料：
  - `mushroom_base`（菌菇）
  - `mala_base`（麻辣）
  - `rattan_pepper_base`（藤椒）
- 放入底料消耗 1 个底料物品；底料类型全局唯一，计数设为 64。
- 每向空格放入 1 个食物，立即扣 1 次底料；取出或移动未完成食物不返还。
- 底料计数降到 0 时：
  - 状态显示“空”，水立即消失。
  - 已经扣过次数的食物继续浸泡到完成。
  - 必须等 16 格全部取空后，才能重新加水、再放新底料。
- 冲洗：
  - 条件：16 格全空、底料计数 > 0、容器内有水。
  - 手持水桶右键，消耗水桶并返还空桶。
  - 底料类型清空、底料计数归 0，水保留，状态回到“水”。
  - 可提前换底料，不必耗尽 64 次。

#### 成品与 NBT

- 统一成品：`boiling-cauldron:bobo_chicken`。
- NBT：
  - `OriginalItem`：原料物品 ID，用于 tooltip。
  - `Flavors`：已浸泡底料列表，最多 3 个，允许值 `mushroom`、`mala`、`rattan_pepper`；同种底料不可重复。
- 显示名按固定顺序“菌香 → 辣辣 → 藤椒”组合，与浸泡顺序无关：
  - 1 种：菌香的钵钵鸡 / 辣辣的钵钵鸡 / 藤椒的钵钵鸡。
  - 2 种：菌香辣辣的钵钵鸡 / 菌香藤椒的钵钵鸡 / 辣辣藤椒的钵钵鸡。
  - 3 种：三味钵钵鸡；tooltip 列出菌香 / 辣辣 / 藤椒。
- 再次浸泡：成品可回锅；已有 3 种或同种底料时拒绝；`OriginalItem` 保持不变，只追加 `Flavors`。
- 标签 `#boiling-cauldron:bobo_chicken` 包含成品；口味由 NBT 区分。
- 所有食物均可作为原料；原料 `FoodComponent` 自带的状态效果保留，特殊行为和容器返还仍不保留。
  - 金苹果、附魔金苹果、河豚等原料的状态效果按原概率、时长和等级保留。
  - 蘑菇煲、兔肉煲、蜂蜜瓶等吃完不返还容器。
  - 紫颂果传送、蜂蜜瓶解毒、迷之炖菜 NBT 效果等特殊行为不保留。

#### 食用与效果

- 固定食物值：饱食度 8，饱和度修正值 0.55（实际约 8.8 点）。
- 食用时额外直接增加 2 点饱和度，只加一次；最终约 10.8 点，受当前饱食度上限限制。
- 再次浸泡不会额外增加食物值或这 2 点饱和度；每次食用按固定值结算。
- 由于口味由 NBT 决定，成品不能只依赖固定 `FoodComponent` 状态效果；需要在 `BoboChickenItem` 的食用逻辑中读取 `Flavors` 并施加效果。
- 底料效果：
  - 菌菇：生命恢复 I，30 秒。
  - 麻辣：力量 I，30 秒。
  - 藤椒：抗性提升 I，30 秒。
- 食用带多种口味的成品时，分别施加对应效果。
- 不叠加规则：
  - 已有同类效果剩余时间 < 30 秒：刷新到 30 秒。
  - 已有同类效果剩余时间 ≥ 30 秒：不处理。
  - 不延长总时长、不提升等级。
  - 若已有更高等级效果，不降级；仅在现有等级不高于本效果时刷新。
- 原料 `FoodComponent` 自带的状态效果保留；先应用原料效果，再应用底料效果；同种效果按底料不叠加规则处理。

#### 破坏与边界

- 破坏容器：掉落容器方块和 16 格内所有食物。
  - 未完成：掉落原始食物。
  - 已完成：掉落对应 `bobo_chicken`（含 NBT）。
- 水、底料类型、底料计数、所有进度清零。
- 取出或移动未完成食物：该格进度清零，底料次数不返还；不额外提示。
- 多人同时操作时，服务端权威校验底料计数、格子状态和取出操作，避免复制。
- 第一版不实现竹签。

#### 代码注意点

- `BoboChickenPotBlock.java:39` 已经返回 `BlockRenderType.MODEL`，不要删除。
- `BlockWithEntity` 默认渲染类型是 `INVISIBLE`；删掉该覆写或改成普通 `Block` 会导致自定义模型不显示。
- 静态方块模型不需要 `BlockEntityRenderer`；BlockEntity 只负责数据、同步和 GUI。
- 模型只改变外观；如果锅的碰撞箱或轮廓需要变化，需额外覆写 `getCollisionShape` / `getOutlineShape`。
- 透明贴图可能需要注册方块渲染层；这不影响模型识别，但会影响透明效果。

#### 模型无法识别的常见原因

- 使用了 `.bbmodel`、Bedrock `.geo.json` 或 Java Entity 格式，而不是 Java Block/Item。
- 文件夹写错：`model/block`、`models/blocks`、`blockstate` 少写复数。
- blockstate 中写成 `boiling-cauldron:models/block/bobo_chicken_pot.json`。
- 资源路径漏命名空间，导致被解析为 `minecraft:block/...`。
- JSON 中保留 `.json` 后缀。
- 贴图写成 `textures/block/...`；正确写法是 `boiling-cauldron:block/...`。
- 模型里的纹理键与 `textures` 中的键不一致。
- blockstate 的 `variants` 与方块属性不匹配；当前方块没有属性，应为 `""`。
- 模型或贴图文件名包含大写、空格、中文。
- JSON 有注释、尾逗号或其他语法错误。
- 模型放进 `src/main/generated`；模型应放在 `src/main/resources`。
- blockstate 或 item 模型仍指向 `minecraft:block/cauldron`、`minecraft:item/cauldron`。

模型不显示时先看 `latest.log` 中的 `Unable to load model` 或 `Missing texture`。只替换模型不需要 datagen 或 build；按 `F3+T` 重载资源，未刷新则重启客户端。

## 与 P3 的关系

钵钵鸡和麻辣烫都应复用同一套“底料类型 + 水/汤底状态 + 槽位与计时”的数据模型：
